Step 2

Chat · talk · react

A persistent now-playing strip stays synced to the host. Voice mic toggle (mute-by-default, emerald "live" ring), the 9-emoji quick bar, and reactions that float up — broadcast to everyone, including the TV overlay.

What this is built on

The companion is mostly a new surface over plumbing Aurora already ships. The green cards are existing systems we point a phone at; the purple cards are the genuinely new work.

Already exists

Room socket & chat

The phone opens /ws/party-room just like the desktop — chat, reaction, participant-join, presence all flow today.

Already exists

Voice mesh

lib/voice.ts is a browser WebRTC mesh — mute-by-default, speaking meters. Mobile Safari/Chrome already support it.

Already exists

Emoji reactions

Same 9-emoji set and sendReaction action. Reactions fired from the phone surface on the TV overlay too.

New work

Mobile route + shell

A dedicated /join route, mobile-first layout, "second screen" mode that opens the room socket without the sync/video socket.

New work

QR + low-friction auth

QR on the host screen, plus a party-guest token (modeled on the existing ScopeCast token) so friends join with just a display name — no full account.

New work

Voice at scale

The mesh tops out ~4 people. A bigger party needs a server-side audio SFU — the one substantial backend lift (see the plan).
